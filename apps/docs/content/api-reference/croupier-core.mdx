# CroupierCore

The main engine class. Manages game state, dispatches actions, runs the phase machine, and emits events.

## Constructor

```typescript
new CroupierCore(config: CroupierConfig, players: PlayerId[], options?: CroupierCoreOptions)
```

- **`config`** — The game configuration (plugin export)
- **`players`** — Array of player IDs participating in the game
- **`options`** — Optional settings

### CroupierCoreOptions

```typescript
interface CroupierCoreOptions {
  seed?: number;
}
```

- **`seed`** — Optional seed for the random number generator (for reproducible games)

### Example

```typescript
import { CroupierCore } from "@croupier/core";
import { createValuesCardConfig } from "@croupier/plugin-values-card";

const game = new CroupierCore(
  createValuesCardConfig(),
  ["alice", "bob"],
  { seed: 42 },
);
```

## Methods

### `dispatch(playerId, actionName, payload?)`

Dispatches a player action. This is the primary way to interact with the game.

```typescript
dispatch(
  playerId: PlayerId,
  actionName: string,
  payload?: unknown
): DispatchResult
```

Returns:

```typescript
interface DispatchResult {
  ok: boolean;
  error?: string;
}
```

**Example:**

```typescript
const result = game.dispatch("alice", "playCard", { cardId: "card_1" });
if (!result.ok) {
  console.error(result.error); // "Not your turn" | "Card not in hand" | etc.
}
```

### `getState()`

Returns the full, unmasked game state. **Use only on the server side** or in tests.

```typescript
getState(): GameState
```

### `getEngineState()`

Returns the current engine state (phase, stage, current players, finished status).

```typescript
getEngineState(): EngineState
```

```typescript
interface EngineState {
  phase: string;
  stage?: string;
  currentPlayers: PlayerId | PlayerId[];
  finished: boolean;
  result?: GameResult;
}
```

### `getPlayerView(playerId)`

Returns the masked state for a specific player. Returns `undefined` if no `view.playerView` is configured.

```typescript
getPlayerView(playerId: PlayerId): unknown | undefined
```

### `getLog()`

Returns the full action log.

```typescript
getLog(): ActionLogEntry[]
```

```typescript
interface ActionLogEntry {
  playerId: PlayerId;
  action: string;
  payload: unknown;
  phase: string;
  stage?: string;
  timestamp: number;
}
```

### `on(event, listener)`

Subscribe to engine events.

```typescript
on<K extends keyof CroupierEvents>(
  event: K,
  listener: (data: CroupierEvents[K]) => void
): void
```

## Snapshot & Restore

The full engine state can be exported as a JSON-serializable snapshot and restored on another process or instance (for example, state kept in Redis behind several WebSocket servers).

### `toSnapshot(options?)`

```typescript
toSnapshot(options?: { logLimit?: number }): CroupierSnapshot<S>
```

Includes the game state, players, current players, phase/stage, finished/result, the seeded random state and the action log. `logLimit` keeps only the most recent N log entries (`0` drops the log). Game state and action payloads must be JSON-serializable.

### `CroupierCore.fromSnapshot(config, snapshot)`

```typescript
static fromSnapshot<S>(config: CroupierConfig<S>, snapshot: CroupierSnapshot<S>): CroupierCore<S>
```

Recreates the engine without re-running `setup()` or any `onEnter` hook. Throws if the snapshot `format`/`version` is unsupported, it was produced by a different game (`config.name`), or its phase/stage no longer exists.

### `getRevision()`

A counter incremented on every successful `dispatch`, `addPlayer` and `endSession`. Unlike `actionCount` it never resets on phase changes, so it can serve as an optimistic-lock version:

```typescript
const snap = JSON.parse(await redis.get(key));
const engine = CroupierCore.fromSnapshot(config, snap);
const res = engine.dispatch(playerId, action, payload);
if (res.ok) {
  // Save only if nobody else saved since we loaded snap.revision; otherwise reload and retry
  await saveIfRevision(key, snap.revision, JSON.stringify(engine.toSnapshot()));
}
```

### Randomness

Use `ctx.random` (`shuffle`, `integer`, `pick`, `next`) inside actions and hooks instead of `Math.random`. It continues the same seeded sequence used by `setup()`, and its state is part of the snapshot, so a restored engine produces the same results for the same dispatches.

### Testing plugins

`@croupier/core/testing` provides `runSnapshotRoundTrip(config, players, { seed, maxSteps, decide })`, which plays a game (with `config.bot` by default) and checks before and after every dispatch that an engine restored from a JSON round-tripped snapshot behaves identically.

## Events

```typescript
interface CroupierEvents<S extends GameState = GameState> {
  stateChange: { state: S; engine: EngineState };
  phaseChange: { from: string; to: string; stage?: string };
  stageChange: { phase: string; from?: string; to?: string };
  action: ActionLogEntry;
  gameEnd: { result: GameResult; state: S };
}
```

### `stateChange`

Emitted after every successful dispatch. Provides the updated state and engine state.

### `phaseChange`

Emitted when the game transitions to a new phase.

### `stageChange`

Emitted when a stage changes within the current phase.

### `action`

Emitted after an action is executed and logged.

### `gameEnd`

Emitted when the game ends (via end conditions).

## Bot Support

Use `BotManager` to run automated players:

```typescript
import { CroupierCore, BotManager, createBotId } from "@croupier/core";

const botIds = ["bot:Alice", "bot:Bob"];
const game = new CroupierCore(config, ["player1", ...botIds]);

const botManager = new BotManager(game, botIds, { delayMs: 1000 });
botManager.start();
// Bots will automatically take actions based on config.bot strategy

// Stop when done
botManager.stop();
```
