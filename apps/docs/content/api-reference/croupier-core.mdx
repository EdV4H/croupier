# CroupierCore

The main engine class. Manages game state, dispatches actions, runs the phase machine, and emits events.

## Constructor

```typescript
new CroupierCore(config: CroupierConfig, players: PlayerId[], options?: CroupierCoreOptions)
```

- **`config`** — The game configuration (plugin export)
- **`players`** — Array of player IDs participating in the game
- **`options`** — Optional settings

### CroupierCoreOptions

```typescript
interface CroupierCoreOptions {
  seed?: number;
}
```

- **`seed`** — Optional seed for the random number generator (for reproducible games)

### Example

```typescript
import { CroupierCore } from "@croupier/core";
import { createValuesCardConfig } from "@croupier/plugin-values-card";

const game = new CroupierCore(
  createValuesCardConfig(),
  ["alice", "bob"],
  { seed: 42 },
);
```

## Methods

### `dispatch(playerId, actionName, payload?)`

Dispatches a player action. This is the primary way to interact with the game.

```typescript
dispatch(
  playerId: PlayerId,
  actionName: string,
  payload?: unknown
): DispatchResult
```

Returns:

```typescript
interface DispatchResult {
  ok: boolean;
  error?: string;
}
```

**Example:**

```typescript
const result = game.dispatch("alice", "playCard", { cardId: "card_1" });
if (!result.ok) {
  console.error(result.error); // "Not your turn" | "Card not in hand" | etc.
}
```

### `getState()`

Returns the full, unmasked game state. **Use only on the server side** or in tests.

```typescript
getState(): GameState
```

### `getEngineState()`

Returns the current engine state (phase, stage, current players, finished status).

```typescript
getEngineState(): EngineState
```

```typescript
interface EngineState {
  phase: string;
  stage?: string;
  currentPlayers: PlayerId | PlayerId[];
  finished: boolean;
  result?: GameResult;
}
```

### `getPlayerView(playerId)`

Returns the masked state for a specific player. Returns `undefined` if no `view.playerView` is configured.

```typescript
getPlayerView(playerId: PlayerId): unknown | undefined
```

### `getLog()`

Returns the full action log.

```typescript
getLog(): ActionLogEntry[]
```

```typescript
interface ActionLogEntry {
  playerId: PlayerId;
  action: string;
  payload: unknown;
  phase: string;
  stage?: string;
  timestamp: number;
}
```

### `on(event, listener)`

Subscribe to engine events.

```typescript
on<K extends keyof CroupierEvents>(
  event: K,
  listener: (data: CroupierEvents[K]) => void
): void
```

### `getRevision()`

Returns a monotonic revision number, incremented on every state mutation (successful `dispatch`, `addPlayer`, `endSession`). Use it for optimistic locking when persisting snapshots.

## Snapshots

The engine state can be exported as a JSON-serializable snapshot and restored later — for example on another server instance. This lets you keep game state in an external store (Redis, Durable Object storage, …) and process any room's messages on any instance.

### `toSnapshot(options?)`

```typescript
toSnapshot(options?: { log?: boolean; logLimit?: number }): CroupierSnapshot<S>
```

- **`log`** — Include the action log (default: `true`)
- **`logLimit`** — Keep only the most recent N log entries

The snapshot contains the game state, players, current players, last player, action count, phase, stage, finished flag, result, PRNG state, `revision`, the game name and a `formatVersion`.

### `CroupierCore.fromSnapshot(config, snapshot)`

```typescript
static fromSnapshot<S>(config: CroupierConfig<S>, snapshot: CroupierSnapshot<S>): CroupierCore<S>
```

Restores an engine. `setup()` and `onEnter` hooks are **not** re-run, and no events are emitted. Throws if `formatVersion` is not `SNAPSHOT_FORMAT_VERSION`, if the snapshot belongs to a different game (`config.name`), or if its phase/stage does not exist in `config`.

Event listeners are not part of the snapshot — subscribe again on the restored engine.

### Example: optimistic locking

```typescript
import { CroupierCore } from "@croupier/core";

async function handleAction(roomId: string, playerId: string, action: string, payload: unknown) {
  for (let attempt = 0; attempt < 3; attempt++) {
    const stored = JSON.parse(await redis.get(roomId));
    const engine = CroupierCore.fromSnapshot(config, stored);

    const result = engine.dispatch(playerId, action, payload);
    if (!result.ok) return result;

    // Save only if nobody else wrote in the meantime
    const saved = await compareAndSet(roomId, stored.revision, JSON.stringify(engine.toSnapshot()));
    if (saved) return result;
  }
  throw new Error("Too many concurrent updates");
}
```

## Events

```typescript
interface CroupierEvents<S extends GameState = GameState> {
  stateChange: { state: S; engine: EngineState };
  phaseChange: { from: string; to: string; stage?: string };
  stageChange: { phase: string; from?: string; to?: string };
  action: ActionLogEntry;
  gameEnd: { result: GameResult; state: S };
}
```

### `stateChange`

Emitted after every successful dispatch. Provides the updated state and engine state.

### `phaseChange`

Emitted when the game transitions to a new phase.

### `stageChange`

Emitted when a stage changes within the current phase.

### `action`

Emitted after an action is executed and logged.

### `gameEnd`

Emitted when the game ends (via end conditions).

## Bot Support

Use `BotManager` to run automated players:

```typescript
import { CroupierCore, BotManager, createBotId } from "@croupier/core";

const botIds = ["bot:Alice", "bot:Bob"];
const game = new CroupierCore(config, ["player1", ...botIds]);

const botManager = new BotManager(game, botIds, { delayMs: 1000 });
botManager.start();
// Bots will automatically take actions based on config.bot strategy

// Stop when done
botManager.stop();
```
