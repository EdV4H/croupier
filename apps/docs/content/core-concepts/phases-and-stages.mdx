# Phases & Stages

Phases represent the major states of your game. Stages are optional sub-states within a phase.

## Phases

Define phases in your `CroupierConfig`:

```typescript
const config: CroupierConfig<MyState> = {
  // ...
  initialPhase: "betting",
  phases: {
    betting: {
      allowedActions: ["fold", "check", "call", "raise"],
      turnOrder: ROUND_ROBIN,
      transitions: [
        { target: "showdown", guard: (ctx) => isBettingComplete(ctx.game) },
      ],
    },
    showdown: {
      allowedActions: [],
      onEnter: (game) => resolveWinner(game),
      always: [
        { target: "betting", guard: (ctx) => ctx.game.playersRemaining > 1 },
      ],
    },
  },
};
```

### Phase Transitions

Phases use two arrays for guard-based transitions:

- **`transitions[]`** — Evaluated when the turn order completes (all players have acted) or a stage finishes with `"__done__"`.
- **`always[]`** — Evaluated after every state change. Use for auto-advancing phases.

Each entry is a `GuardedTransition`:

```typescript
interface GuardedTransition<S> {
  target: string;                          // Phase name to transition to
  guard: (ctx: CroupierContext<S>) => boolean;  // Condition to check
}
```

Transitions are evaluated in array order — the first matching guard wins.

### Phase Lifecycle

1. **`onEnter(game, ctx)`** — Called when entering the phase. Use for setup (deal cards, reset counters).
2. **Turn order initialization** — `turnOrder.first()` determines who goes first.
3. **Always-check** — `always[]` guards are evaluated. If any match, the phase transitions immediately.
4. **Player actions** — Players dispatch actions until the turn order completes or a transition triggers.
5. **Transition check** — After turn order completes, `transitions[]` guards are evaluated.
6. **`onExit(game, ctx)`** — Called when leaving the phase.

### Auto-Advancing Phases

Phases with no `allowedActions` (or an empty array) automatically advance. This is useful for setup phases:

```typescript
phases: {
  turnStart: {
    // No allowedActions — auto-advances after onEnter
    onEnter: (game) => {
      game.currentMana += 1;
      drawCard(game);
    },
    always: [
      { target: "main", guard: () => true },
    ],
  },
  main: {
    allowedActions: ["playCard", "attack", "endTurn"],
    // ...
  },
}
```

## Stages

Stages add a sub-state within a phase. They're useful when a phase has distinct sub-steps (e.g., draw then discard).

```typescript
phases: {
  play: {
    stages: {
      waitingForDraw: {
        allowedActions: ["drawFromDeck", "drawFromDiscard"],
        always: [
          { target: "waitingForDiscard", guard: (ctx) => ctx.game.drewCard },
        ],
      },
      waitingForDiscard: {
        allowedActions: ["discardCard"],
        always: [
          { target: "__done__", guard: (ctx) => ctx.game.discarded },
        ],
      },
    },
    initialStage: "waitingForDraw",
    transitions: [
      { target: "presentation", guard: (ctx) => ctx.game.deck.length === 0 },
      { target: "play", guard: () => true }, // loop back
    ],
  },
}
```

### The `__done__` Sentinel

When a stage's `always[]` transition targets `"__done__"`, it signals that the stage sequence is complete. The engine then evaluates the parent phase's `transitions[]` to determine the next phase.

### Stage Lifecycle

1. **`onEnter(game, ctx)`** — Called when entering the stage.
2. **Turn order** — Uses the stage's `turnOrder` if defined, otherwise the phase's.
3. **Actions** — Players dispatch actions allowed by the stage's `allowedActions`.
4. **`always[]`** — After each action, stage transitions are checked. Target can be a stage name or `"__done__"`.
5. **`onExit(game, ctx)`** — Called when leaving the stage.

## Transition Priority

When checking transitions:

1. If in a stage, the **stage's `always[]`** transitions are checked first.
2. If a stage transitions to `"__done__"`, the **phase's `transitions[]`** are checked.
3. If not in a stage, the **phase's `transitions[]`** are checked on turn order completion.
4. The **phase's `always[]`** transitions are checked after every state change.
